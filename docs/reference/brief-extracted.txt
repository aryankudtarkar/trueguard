 
Techfest 2026-27 
TrueFoundry Forge-a-thon 
Objective 
Every engineer has used an AI coding tool, and most have an opinion about where 
it falls short: it loses track of the file you care about, it rewrites a function you did 
not ask it to touch, it confidently edits a symbol that does not exist. This 
competition asks you to build the thing you have opinions about, on the same 
foundation that production agents run on. 
 
Your mission is to ship a coding agent as a Visual Studio Code extension whose 
agent loop runs on TrueForge, TrueFoundry's open-source agent harness. Given a 
real repository, it must read the code, plan a change, edit several files, and present 
those edits for review inside the editor. You choose the AI model it runs on. 
TrueForge handles the loop, so your energy goes where the difficulty really is: 
deciding what the model sees, and making the editor experience safe and fast. 
Challenge Question 
How would you build an editor-native coding agent on TrueForge that finds the right 
code in a repository larger than any model's context window, makes a multi-file 
change the user never had to spell out file by file, shows every change for review 
before it touches disk, and keeps working when the model behind it fails? 
Track-specific specs/deliverables 
What You Must Build 
Five capabilities are mandatory. A submission missing one can still be scored, but it 
will score poorly on capability coverage. This is the floor, not the contest; the 
contest is in how well you build them. 
 

 
1. Inline edit. The user selects a region of code, presses a keybinding, and 
types an instruction in plain language. Your extension returns a proposed diff 
rendered in the editor, which the user accepts or rejects. A chat reply the 
user must copy and paste does not count. 
2. Agent mode. A panel where a single request drives a TrueForge agent 
through a tool loop (read file, search, write file, run a terminal command) 
until the task is done or the agent gives up. It must carry out a change 
spanning at least three files without the user naming them. Finding them is 
the agent's job. 
3. Context assembly. Explicit @file and @symbol mentions, plus automatic 
retrieval of relevant code the user did not mention. This is the intellectual 
core of the problem. Once a repository no longer fits in a context window, 
what you put in and what you leave out decides whether the agent works at 
all. TrueForge's context-engineering features are there to be used, and using 
them well is scored. 
4. Diff review. Changes are presented hunk by hunk with a visible preview, 
and the user accepts or rejects each one. No silent writes to disk. An applied 
change must be undoable. 
5. Streaming and cancellation. Tokens appear as they arrive through 
TrueForge's streaming events. The user can interrupt a generation mid-flight 
and the editor never blocks. A cancelled run leaves the workspace consistent, 
with no half-applied edits. 
Out of scope (not scored; time spent here is time lost): tab completion or 
fill-in-the-middle; training, fine-tuning or hosting your own model; a hosted 
backend, database or deployed service beyond TrueForge in local mode; user 
accounts or authentication; publishing to the VS Code Marketplace. 
Bring Your Own Model 
You choose the AI model and where it runs. Any of the following is acceptable, 
configured in TrueForge: a paid API from any provider, a provider's free tier, a 
model served through an AI gateway, or an open-source model running on your 
own machine behind an OpenAI-compatible endpoint. Your extension must work 
 

 
with whatever model TrueForge is configured with; it must not depend on one 
provider. 
Fairness. Points are awarded for behaviours your extension demonstrates, never 
for how clever the model's answers are. A team using a free or local model that 
demonstrates every behaviour scores exactly the same as a team using an 
expensive model. Judges score what the extension does on screen: whether a diff is 
rendered, whether files were discovered, whether a cancelled run left the 
workspace clean. The organisers may ask any shortlisted team to repeat a fixed 
task live with a model of the organisers' choice before the shortlist is final, so build 
for any model, not for one. 
Declare it. Your write-up must state every model you used, where it ran, and 
roughly what it cost. Never commit an API key to your repository; ship an example 
configuration file instead. 
Building on Open Source 
You are encouraged to reuse open-source code for the editor side of the problem: 
the webview, diff rendering, keybindings and VS Code plumbing from projects such 
as Cline, Continue, Roo Code or opencode. Rebuilding a diff viewer from scratch is 
not a demonstration of skill. The agent loop, however, must be replaced with 
TrueForge; keeping an upstream project's own loop is an eligibility failure. We score 
your delta, not your repository: 
● Declare your fork point in the README: the upstream repository URL and the 
exact commit you started from. 
● Preserve the upstream licence and attribution. A licence violation is an 
eligibility failure. 
● Describe what you changed and why, in the README or in your write-up. 
Judges read your git history from the declared fork commit forward.

Evaluation Criteria 
Eligibility gate (pass or fail, checked first) 
The agent loop must run on TrueForge (github.com/truefoundry/trueforge). 
Concretely: 
● Your VS Code extension is a client of a TrueForge agent. It creates sessions 
and sends turns through the TrueForge HTTP API or the TypeScript SDK, and 
renders the streamed events in the editor. 
● Your editor's capabilities (read file, search the workspace, propose a write, 
run a command) are exposed to the agent as MCP tools, so the agent, not 
the extension, decides what to read and change. 
● Run TrueForge in local mode on your own machine (npx 
 

 
@truefoundry/trueforge@latest). Nothing needs to be deployed. The sandbox 
feature is optional and not required for any fixed task. 
● Your model is configured in TrueForge as a catalog provider or an 
OpenAI-compatible endpoint. Your extension must not call a model provider 
directly. 
● Your demo video must briefly show the TrueForge session for Task B (turns 
and tool calls), and your repository must contain the agent definition you 
used. 
Why this rule: a harness exists so that you do not spend your month rebuilding 
streaming, session state, tool plumbing and approvals. With those solved, the 
competition is about the two things that separate a good coding agent from a bad 
one: context assembly and a safe, fast editor experience.

Process and shortlist 
● Each submission is scored independently by two judges; the score is the 
mean. A spread of more than 15 points triggers a third judge. 
● The top 15 teams by score are shortlisted for Round 2. Ties break on B, 
then A, then earlier submission time. 
● Before the shortlist is final, each shortlisted team joins a 10-minute video call 
to walk through its code and repeat Task A live with a model chosen by the 
organisers. A team that cannot explain its own submission is replaced by the 
next team in rank. 
● Round 1 scores are published to each team with the anchor selected for 
every criterion. 
Round 2 
The 15 shortlisted teams travel to Techfest, IIT Bombay, for Round 2 on 16 to 18 
December 2026. Round 2 will involve building agents on TrueForge and, in addition, 
raising a Pull Request to the TrueForge repository 
(github.com/truefoundry/trueforge): a contribution to the harness itself, reviewed 
as part of your score. TrueFoundry will provide model credits to every finalist team 
for Round 2, so no team's result depends on the model it can afford. The Round 2 
problem statement, format and judging criteria are shared with all shortlisted teams 
before the finale day, at the same time, so every finalist has equal time to prepare. 
Expect to operate what you build in front of judges, on material you have not seen 
before, and to answer questions on your design.

General rules of the competition 
1. Teams must register online at techfest.org and will receive a Team ID for 
future reference. 
2. The agent loop must run on TrueForge. Extensions that call a model provider 
directly or keep an upstream project's own agent loop are ineligible. 
3. All code must be the team's own work, except for declared forks and ordinary 
dependencies. Open-source libraries and tools may be used with licence 
compliance and credit. 
4. You may use any AI coding tool to build your coding agent. Declare it in the 
write-up; it costs no points. 
5. Models used must be declared in the write-up and configured in TrueForge. 
Hard-coding one provider is not acceptable. 
6. Do not use code from an employer or any private codebase. Use the pinned 
repository and your own work. 
7. Submissions must be public under an open-source licence compatible with any 
upstream project used. By submitting, teams grant TrueFoundry and Techfest, 
IIT Bombay a non-exclusive, perpetual, royalty-free licence to use, modify and 
showcase the submission, and agree that registration details are shared with 
TrueFoundry subject to applicable law. 
8. The organisers' and judges' decisions are final and binding. Techfest reserves 
the right to verify participant details. 
9. Techfest, IIT Bombay, is not responsible for late or lost entries. Links that are 
not public at the deadline are not scored. 
10. The latest information will be available on techfest.org, with registered 
participants notified of changes by email. 
11. All technical, procedural and competition-related queries must be submitted 
 

 
through the Techfest Competition Portal under the Doubt section. Questions 
about TrueForge itself are best asked in the TrueForge community Discord. 
Official announcements come from the email address shown on the 
competition page. Queries sent by email will not be answered. 
12. Plagiarism, copying another team's submission, or sharing a submission 
between teams leads to disqualification of all teams involved.
